# 一、為什麼 UI 框架需要並行?

畫面更新跑在**主執行緒 (main thread)**。如果你在主執行緒做耗時的事(網路、讀檔、大量運算),主執行緒被佔住 → **畫面凍結、掉幀、轉圈**。

並行的目標:**把耗時工作丟到背景做,做完再回主執行緒更新畫面**。Swift 用 `async/await` 讓這件事寫起來像同步程式碼一樣直覺,而不用一堆巢狀 callback。

# 二、`async` / `await` 的本質:可暫停的函式

- **`async`**:標記函式「**可能會暫停**」(等網路、等磁碟)。它不保證在背景跑,只是「**可以在中途讓出執行緒**」。
- **`await`**:呼叫 async 函式的地方。意思是「**這裡可能暫停,讓出執行緒給別人用;結果回來再從這裡繼續**」。

```swift
func loadUser() async throws -> User {
    let (data, _) = try await URLSession.shared.data(from: url)  // 暫停點:等網路
    return try JSONDecoder().decode(User.self, from: data)       // 回來後繼續
}
```

關鍵理解:**`await` 不是「卡住等」,而是「掛起、讓執行緒去做別的事、好了再回來」**。所以在主執行緒 `await` 網路,畫面依然流暢 —— 因為等待期間主執行緒是空出來的。

> 對照舊世界:這取代了 completion handler(`{ result in ... }`)的巢狀地獄。`async/await` 讓「等待」變成一行 `await`,程式碼由上往下讀。

# 三、`Task`:並行的基本單位

`async` 函式只能在「並行情境」裡呼叫。`Task { }` 就是建立一個並行情境的入口。

```swift
Task {
    let user = try await loadUser()    // 在這個 Task 裡可以 await
    print(user.name)
}
```

在 SwiftUI 裡,你**幾乎不該手寫 `Task { }`**,而是用 [[生命週期與 task#`.task` —— 非同步載入的首選|`.task` modifier]] —— 它是「綁定 View 生命週期、會自動取消」的 `Task`。手寫 `Task` 的取消要自己管,容易漏。

## `Task` 的種類

| 寫法 | 特性 |
| --- | --- |
| `Task { }` | 繼承當前情境(actor、優先序);最常用 |
| `Task.detached { }` | **不繼承**情境(脫離 actor、不自動在 MainActor)→ 慎用,容易引發資料競爭 |

# 四、取消 (Cancellation) 是合作式的

這是最常被忽略、卻最重要的觀念。

> **取消只是「設一個旗標」,系統不會強制中止你的程式碼。** 你的程式碼必須「**願意檢查並理會**」這個旗標,才會真的停下來。

`.task` 在 View 消失時會「送出取消訊號」,但:

```swift
.task {
    for item in hugeList {
        try Task.checkCancellation()    // ✅ 主動檢查;被取消會丟錯而中止
        process(item)                    // 沒有這行檢查的話,迴圈會跑完才停
    }
}
```

檢查取消的兩種方式:

- `Task.isCancelled` → 回傳 `Bool`,自己決定怎麼收尾(`break`、回傳部分結果)。
- `try Task.checkCancellation()` → 若已取消就丟 `CancellationError`,直接中止。

好消息:**多數系統 API(`URLSession`、`Task.sleep`…)已內建對取消的反應** —— 被取消時它們會自己丟錯。你只需要在「**自己寫的長迴圈 / 重運算**」裡手動檢查。

```swift
.task(id: query) {
    try? await Task.sleep(for: .milliseconds(300))   // debounce;被取消(query 又變)會自動中止
    guard !Task.isCancelled else { return }
    results = await search(query)
}
```

> 上面這招就是 **debounce**:`query` 一直變時,舊 Task 不斷被 `.task(id:)` 取消,只有「停下來 300ms」的那次才真的查詢。

# 五、`@MainActor`:保證在主執行緒更新 UI

**所有更新 UI 的程式碼必須在主執行緒。** Swift 用 `actor` 機制中的 `@MainActor` 來表達「這段一定在主執行緒跑」。

好消息:**SwiftUI 的 `View` 已經是 `@MainActor`**,`.task`、`.onChange` 的閉包也都在主執行緒。所以單純在 `.task` 裡 `await` 再更新 `@State`,**預設就是安全的**:

```swift
@State private var user: User?
.task {
    user = try? await loadUser()   // loadUser 內部去背景跑,回來這行已在主執行緒 → 安全
}
```

什麼時候要自己標 `@MainActor`?當你把邏輯**抽到 View 外面的物件**(如 ViewModel),而它要更新會驅動畫面的屬性時:

```swift
@MainActor                          // 整個類別的方法預設在主執行緒
@Observable
class ProfileModel {
    var user: User?
    func load() async {
        user = try? await api.fetchUser()   // 更新會驅動畫面的屬性 → 需在主執行緒
    }
}
```

> 這也是 [[架構模式 MVVM#ViewModel 與並行|MVVM]] 裡 ViewModel 常標 `@MainActor` 的原因。

# 六、同時做多件事:並行而非串行

預設 `await` 是**串行**的 —— 一個做完才做下一個:

```swift
let a = await loadA()    // 等 1 秒
let b = await loadB()    // 再等 1 秒 → 總共 2 秒
```

若兩件事互不相依,應該**同時發動**。

## `async let`:固定數量的並行

```swift
async let a = loadA()    // 立刻開始,不等
async let b = loadB()    // 也立刻開始
let (x, y) = try await (a, b)   // 在這裡才一起等 → 總共約 1 秒
```

## `TaskGroup`:數量不定的並行

要對「一個清單」的每個元素都並行處理時:

```swift
let images = try await withThrowingTaskGroup(of: Image.self) { group in
    for url in urls { group.addTask { try await download(url) } }   // 全部同時下載
    var result: [Image] = []
    for try await img in group { result.append(img) }               // 收集結果
    return result
}
```

> 重點:`async let` 用於「**我知道有 A、B、C 幾件事**」;`TaskGroup` 用於「**有一串、數量不定的事**」。兩者都是結構化的 —— 離開作用域時子任務會被自動等待 / 取消。

# 七、`AsyncSequence`:會「持續吐值」的非同步串流

不是「一次拿一個結果」,而是「**隨時間陸續來的多個值**」(如即時訊息、檔案逐行、感測器)。用 `for await` 接:

```swift
.task {
    for await message in chat.messages {     // 每來一則就進來一次
        if Task.isCancelled { break }
        messages.append(message)
    }
}
```

`.onChange` 之於「值變化」,`AsyncSequence` 之於「值的串流」。離開畫面時 `.task` 取消,迴圈也跟著結束。

# 八、資料競爭與 `Sendable`(概念認識)

並行最大的危險:**兩條執行緒同時讀寫同一塊記憶體** → 結果不可預期、難重現的崩潰。Swift 6 的並行檢查會在編譯期幫你擋掉大部分這種錯。

兩個你會遇到的名詞:

- **`actor`**:一種「**一次只允許一個任務存取其內部狀態**」的引用型別 —— 用「排隊」消除資料競爭。需要在背景安全共享可變狀態時用。
- **`Sendable`**:標記「這個型別可以**安全地跨執行緒傳遞**」。值類型(struct/enum)多半天生 `Sendable`;含可變引用的 class 則不是。

```swift
actor ImageCache {                 // 內部 dict 的存取自動序列化,不會競爭
    private var cache: [URL: Image] = [:]
    func image(for url: URL) -> Image? { cache[url] }
    func store(_ img: Image, for url: URL) { cache[url] = img }
}
// 用的時候要 await,因為要「排進這個 actor 的隊伍」
let img = await cache.image(for: url)
```

> 實務上:**UI 與 ViewModel 用 `@MainActor`(都在主執行緒,天然無競爭);需要背景共享的快取 / 狀態用 `actor`。** 純資料用值類型傳遞最省心。

# 九、SwiftUI 資料載入的標準骨架

把前面整合成一個可重用的範式 —— 用 enum 表達載入狀態(呼應 [[Swift 型別與關鍵字基礎#四、`enum` —— 列舉(比 C# 強大很多)|enum 帶關聯值]]):

```swift
enum LoadState<T> {
    case idle, loading
    case loaded(T)
    case failed(Error)
}

@MainActor @Observable
class FeedModel {
    var state: LoadState<[Post]> = .idle
    func load() async {
        state = .loading
        do    { state = .loaded(try await api.fetchPosts()) }
        catch { state = .failed(error) }
    }
}

struct FeedView: View {
    @State private var model = FeedModel()
    var body: some View {
        Group {
            switch model.state {
            case .idle, .loading: ProgressView()
            case .loaded(let posts): List(posts) { Text($0.title) }
            case .failed(let err): Text("錯誤:\(err.localizedDescription)")
            }
        }
        .task { await model.load() }    // 出現時載入、離開自動取消
    }
}
```

這個骨架同時處理了:載入中 UI、錯誤 UI、自動取消、主執行緒更新 —— 是大多數「拉資料顯示」畫面的標準寫法。

# 十、總結

- **目的**:把耗時工作移出主執行緒,畫面不卡。
- **`async/await`**:`await` 是「掛起讓出、好了再回來」,不是「卡住等」。
- **`Task`**:並行入口;在 SwiftUI 用 `.task` 而非手寫 `Task`(自動取消)。
- **取消是合作式**:自己的長迴圈要檢查 `Task.isCancelled` / `checkCancellation()`;系統 API 多半已內建。
- **`@MainActor`**:更新 UI 的程式碼要在主執行緒;View 已是 MainActor,抽出的 ViewModel 記得標。
- **並行**:`async let`(固定幾件)/ `TaskGroup`(一串不定數量)。
- **串流**:`AsyncSequence` + `for await`。
- **安全**:`actor` 排隊消除競爭、`Sendable` 標記可跨執行緒;UI/VM 走 `@MainActor` 最省心。
- **標準骨架**:`enum LoadState` + `@MainActor @Observable` model + `.task`。
